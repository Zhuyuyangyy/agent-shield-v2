## 一、发明名称

**一种面向多智能体系统的行为链风险归因与反事实治理方法及系统**

---

## 二、技术领域

本发明属于人工智能安全治理领域，具体涉及多智能体系统（Multi-Agent System）中的行为链风险传播建模、因果归因与反事实治理推演技术。

---

## 三、背景技术与问题

### 3.1 背景

随着大型语言模型（LLM）驱动的 AI Agent 在企业场景中普及，单一 AI Agent 的工具调用风险审计已不能满足复杂场景需求。真实企业环境中，多个 AI Agent 通常以协作链形式工作：

```
财务 Agent → 客户数据 Agent → 邮件发送 Agent
代码 Agent → 数据库 Agent → 文件导出 Agent
```

这种协作链中，单个 Agent 的风险可能较低，但通过行为链传播后，风险逐级放大，最终导致系统性数据泄露或安全事件。现有技术无法建模这种跨 Agent 的风险传播过程。

### 3.2 现有技术缺陷

1. **单 Agent 审计局限**：现有方案仅对单一 Agent 的工具调用进行审计，无法感知该 Agent 在整个协作链中的位置及其对下游 Agent 的风险影响。

2. **缺乏风险传播建模**：无法识别风险在多 Agent 调用链中如何逐级放大（例如 A:0.05 → B:0.75 → C:0.98）。

3. **无法定位根因 Agent**：当多 Agent 协作链发生安全事件时，现有方案无法判定哪个 Agent 的哪个行为是真正的根因。

4. **缺乏反事实推演能力**：现有方案只能报告"当前发生了什么"，无法回答"如果当时阻断 A，结果会不会不同"这类反事实问题。

## 四、发明技术方案

### 4.1 核心思路

本发明提出一种面向多智能体系统的行为链风险归因与反事实治理方法，包括以下步骤：

```
S1. 构建多主体行为链图
S2. 识别跨 Agent 风险传播路径
S3. 计算根因 Agent 与责任度
S4. 生成治理决策（BLOCK / ALLOW / DEGRADE）
S5. 执行 What-if 反事实推演
S6. 输出统一治理报告
```

### 4.2 详细技术方案

#### S1：构建多主体行为链图

对多 Agent 系统中的每一次工具调用，在图中创建一个节点，记录：

- 调用者 Agent ID
- 工具名称与参数脱敏摘要
- V2 影子审计风险评分（shadow_risk_score）
- 继承自上游 Agent 的风险量（inherited_risk）
- 节点当前风险状态（safe / medium / high / critical）

对每对有父子关系的 Agent 调用，在图中创建一条有向边，记录：

- 边类型（calls / data_flow / invokes / returns）
- 风险流量（risk_flow = 下游节点 shadow_risk_score）

```python
@dataclass
class BehaviorNode:
    node_id: str
    agent_id: str
    tool_name: str
    shadow_risk_score: float      # V2 影子评分
    inherited_risk: float         # 从上游继承的风险量
    risk_status: str              # safe/medium/high/critical
    fuse_action: str              # V2 熔断决策

@dataclass
class BehaviorEdge:
    edge_id: str
    from_node_id: str             # 父节点
    to_node_id: str               # 子节点
    edge_type: str                # calls/data_flow/invokes/returns
    risk_flow: float              # 沿此边的风险流量
```

#### S2：识别跨 Agent 风险传播路径

基于行为链图，遍历所有从根节点到叶子节点的有向路径，构建风险传播子图。识别所有"关键因果链"（critical chains），满足以下条件之一：

- 终端节点 risk_status = critical
- 路径长度 > 1 且终端节点 risk_status = high
- 路径中任意节点 inherited_risk > 0.5

每条关键因果链记录：链 ID、根 Agent、终端 Agent、终端风险值、风险放大系数。

#### S3：计算根因 Agent 与责任度

对每条关键因果链，执行反向风险归因：

```python
responsibility_score = (
    direct_risk_score * amplification_factor +
    inherited_risk * chain_length_decay
) / chain_length
```

其中：
- `direct_risk_score`：该节点自身的 V2 影子风险评分
- `amplification_factor`：该节点向下游传播时对风险流量的放大倍数
- `inherited_risk`：该节点从上游继承的风险量
- `chain_length_decay`：因果链长度衰减系数（链越长，每个节点的直接贡献度越低）

取所有因果链中 responsibility_score 最高的 Agent 节点，作为根因 Agent（root_cause_agent）。

#### S4：生成治理决策

基于决策表，根据节点风险状态和因果链属性，生成治理动作：

| 条件 | 动作 | 说明 |
|---|---|---|
| shadow_risk_score >= 0.90 | BLOCK | 高风险节点直接阻断 |
| inherited_risk >= 0.50 且链长 > 2 | BLOCK | 继承高风险的长链阻断 |
| amplification >= 2.0 | UPDATE_RULES | 风险放大器，更新审计规则 |
| inherited_risk >= 0.30 | DEGRADE | 降权该 Agent 权限 |
| 其他 | ALLOW | 记录审计日志后放行 |

每个治理决策包含：

```python
@dataclass
class GovernanceDecision:
    action: str              # BLOCK / ALLOW / DEGRADE / UPDATE_RULES
    target_agent: str        # 目标 Agent ID
    rationale: str            # 决策依据（中文自然语言）
    predicted_effect: float  # 预测干预效果（0~1）
    level: str               # node / chain
```

#### S5：执行 What-if 反事实推演

对每条关键因果链，生成反事实推演场景：

**场景类型 A：早期阻断（block_at_root）**
- 假设在因果链根节点实施阻断，而非终端节点
- 计算：阻断根节点后，终端风险预测降低量

```
如果阻断 FinancialAgent（原风险 0.05），
EmailAgent 终端风险从 0.98 降至 0.03，
风险降低 97.5%，建议采纳。
```

**场景类型 B：提高阈值（raise_threshold）**
- 假设将 BLOCK 阈值从 0.90 提高到指定值
- 评估：提高阈值后，当前因果链是否会被阻断，是否增加漏检风险

每个 What-if 场景输出：

```python
@dataclass
class WhatIfScenario:
    scenario_id: str
    description: str                          # 场景描述（中文）
    hypothetical_change: dict                 # 假设变更内容
    predicted_risk_reduction: float           # 预测风险降低量（0~1）
    predicted_new_score: float               # 干预后的新风险评分
    confidence: float                        # 预测置信度（0~1）
    recommendation: str                       # 建议（采纳/不采纳）
```

#### S6：输出统一治理报告

V3 在 V2 单次工具调用审计基础上，增加以下内容：

```python
@dataclass
class ChainAuditResult:
    session_id: str
    v2_summary: dict                    # V2 影子审计统计
    behavior_graph: dict               # Layer 1 行为图
    causality_report: dict             # Layer 2 因果分析
    governance_report: dict            # Layer 3 治理决策
    overall_risk_level: str            # 综合风险等级
    governance_summary: str            # 治理结论（中文）
```

## 五、实施例

### 实施例：金融 Agent 多主体行为链治理

**场景设置（5 个 Agent，4 条调用边）：**

```
FinancialAgent (root, score=0.05, SAFE)
  ├── CustomerDataAgent (calls, score=0.75, HIGH)
  │     └── EmailAgent (data_flow, score=0.98, CRITICAL)
  └── DataExportAgent (calls, score=0.82, HIGH)
        └── LoggerAgent (calls, score=0.01, SAFE)
```

**执行结果：**

**Layer 1 行为图构建：**
- 5 个节点，4 条边
- EmailAgent 状态 CRITICAL（shadow=0.98, inherited=0.55）

**Layer 2 因果归因：**
- 识别 1 条关键因果链：FinancialAgent → CustomerDataAgent → EmailAgent
- 根因定位：FinancialAgent（responsibility=1.000）

**Layer 3 治理决策：**
- BLOCK EmailAgent（风险 0.98 >= 0.90，直接阻断）
- ALLOW CustomerDataAgent（风险可控）
- ALLOW DataExportAgent（风险可控）

**What-if 反事实：**
- 场景 1（早期阻断）：阻断 FinancialAgent，EmailAgent 风险从 0.98 降至 0.025，风险降低 97.5%，**建议采纳**
- 场景 2（提高阈值）：阈值 0.9→0.95，风险仅降低 3.1%，不建议

**综合治理结论：**
- 整体风险：HIGH
- 阻断 1 个高风险节点，生成 2 个反事实场景，其中 1 个建议采纳

## 六、关键创新点

| # | 创新点 | 技术表述 |
|---|---|---|
| 1 | **多主体行为链风险建模** | 将多 Agent 调用关系建模为有向加权风险图，记录每个节点的影子风险评分和继承风险量 |
| 2 | **基于规则约束的因果链归因** | 基于行为链图和风险传播规则（非严格因果发现），计算每个 Agent 在风险传播中的责任度 |
| 3 | **反事实治理推演** | 对关键因果链生成"阻断早期节点"和"调整阈值"两类反事实场景，量化不同干预策略的效果差异 |
| 4 | **V2+V3 统一治理报告** | 在 V2 单次工具调用审计基础上，融合行为链建模和治理决策输出，实现多层级审计报告 |

## 七、权利要求书大纲

### 独立权利要求

**权1：** 一种面向多智能体系统的行为链风险归因与反事实治理方法，其特征在于，包括：
- S1. 对多 Agent 系统中的每一次工具调用，创建包含调用者 Agent ID、影子风险评分、继承风险量和风险状态的节点，并建立有向边记录 Agent 间调用关系与风险流量，由此构建多主体行为链图；
- S2. 基于所述行为链图，识别所有从根节点到叶子节点的关键因果链；
- S3. 对每条所述关键因果链，基于所述节点的影子风险评分、继承风险量和链长，计算各 Agent 的责任度，定位根因 Agent；
- S4. 根据预设治理决策表，对风险节点生成 BLOCK / ALLOW / DEGRADE / UPDATE_RULES 治理动作；
- S5. 对每条所述关键因果链，执行 What-if 反事实推演，生成阻断早期节点和调整阈值两类场景，量化干预效果；
- S6. 输出包含行为链图、因果归因结果、治理决策和反事实推演结果的统一治理报告。

### 从属权利要求

**权2（权1优选）：** 所述 S1 中，所述影子风险评分由工具调用影子预演引擎产生，包括 SQL 执行风险、权限变更风险和外部通信风险的加权评分。

**权3（权1优选）：** 所述 S2 中，所述关键因果链的识别条件包括：终端节点风险状态为 critical，或路径长度大于一且终端节点风险状态为 high，或路径中任意节点继承风险量大于零点五。

**权4（权1优选）：** 所述 S3 中，所述责任度计算公式为：responsibility_score = (direct_risk_score × amplification_factor + inherited_risk × chain_length_decay) / chain_length。

**权5（权1优选）：** 所述 S4 中，所述治理决策表包括：当影子风险评分大于等于零点九时生成 BLOCK 动作，当继承风险量大于等于零点五且因果链长度大于二时生成 BLOCK 动作，当放大系数大于等于二点零时生成 UPDATE_RULES 动作。

**权6（权1优选）：** 所述 S5 中，所述 What-if 反事实推演包括阻断早期节点场景：在不阻断终端节点的情况下，阻断因果链的根节点，计算阻断根节点后的终端风险降低量，并生成干预建议。

**权7（权1优选）：** 一种计算机可读存储介质，其上存储有计算机程序，所述计算机程序被处理器执行时实现权利要求1至6中任一项所述方法的步骤。

## 八、技术边界说明（专利稳健性）

本专利申请明确采用以下稳健表述：

1. **"因果链归因"** 而非"因果发现"：本方法基于行为链图结构和风险传播规则进行归因，不声称从观测数据中自动发现严格因果关系。

2. **"反事实推演"** 而非"因果推理"：本方法的 What-if 场景基于规则模拟，而非统计因果推断。

3. **"影子风险评分"** 而非"真实风险"：V2 影子模拟产生的评分明确为预测性评分，不声称与实际风险完全对应。

4. **"治理决策"** 而非"最优决策"：本方法生成的 BLOCK/ALLOW 动作是规则驱动的建议动作，不声称为全局最优解。
